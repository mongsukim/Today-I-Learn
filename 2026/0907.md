## 1. 테스트 환경 정합성 `재발 5회+` `심각도: 높음`

> 새 hook·context 의존성을 추가하면서 테스트 render wrapper 업데이트를 빠뜨려 pre-push에서 깨지는 패턴.
> `QueryClientProvider` `ToastProvider` `DesignProvider` 누락이 대표적.

- [ ] 새로 추가한 **useQuery / useMutation / useQueryClient** 가 있으면 해당 컴포넌트 테스트에 **QueryClientProvider**가 있는지 확인
  - `grep -r "useQuery\|useMutation\|useQueryClient" <변경파일>`
- [ ] 새로 추가한 **Context (Toast, Design, ScrollLock 등)** 에 대응하는 Provider가 테스트 wrapper에 있는지 확인
- [ ] 변경된 컴포넌트와 같은 디렉토리에 **\*.test.tsx** 가 있으면 `npx jest --ci <경로>` 실행
- [ ] mock 데이터에 **새로 필요한 필드**(nickname 등)가 빠져 있지 않은지 확인

## 2. 뒤로가기 / 네비게이션 플로우 `재발 6회` `심각도: 높음`

> 새 화면 추가 시 history stack이 어떻게 쌓이는지 사전 시뮬레이션 없이 구현하여, 뒤로가기 시 엉뚱한 화면으로 이동하거나 순환이 생기는 패턴.

- [ ] **navigate(-1)** 사용 시 진입 경로가 2가지 이상이면 목적지가 달라질 수 있다 — 알림/딥링크/탭 전환 모두 확인
- [ ] 스텝 폼(step 1→2→3)에서 **Android back** 시 이전 스텝으로 가는지 / 폼 밖으로 나가는지 의도 확인
- [ ] 완료 화면(접수완료, 예약완료)에서 뒤로가기 시 **폼으로 돌아가지 않는지** 확인 (replace 사용 여부)
- [ ] 바텀시트/팝업 내 링크(약관 상세 등)에서 뒤로가기 시 **바텀시트로 복귀**하는지 확인

## 3. React Query 캐시 무효화 `재발 3회` `심각도: 높음`

> mutation(생성/수정/삭제) 성공 후 관련 목록 쿼리를 invalidate하지 않아 stale 데이터가 보이는 패턴.

- [ ] **mutation onSuccess** 에서 관련 목록 쿼리를 invalidate하는지 확인
  - `queryKeys.도메인.lists()` 또는 `.searches()` 사용 (`도메인.all` 금지)
- [ ] 변경된 데이터를 **다른 화면에서도 표시**하고 있다면 해당 쿼리도 함께 invalidate
  - 예: 글쓰기 → 목록 + 홈 최신글 위젯 둘 다
- [ ] 정렬 파라미터가 포함된 쿼리라면 invalidate 후 **올바른 정렬로 재요청**되는지 확인

## 4. 피그마 디자인 대조 `재발 5회+` `심각도: 중간`

> 1차 구현 후 여백, 아이콘 색상, 문구가 시안과 미세하게 다른 상태로 머지되어 후속 수정 커밋이 발생하는 패턴.

- [ ] **padding / margin / gap** 값이 피그마 Auto Layout 수치와 일치하는지 px 단위로 비교
- [ ] 텍스트 **문구 / 줄바꿈 / 말줄임** 처리가 시안과 동일한지 확인 (특히 긴 텍스트 케이스)
- [ ] 아이콘 **색상·사이즈**가 디자인 토큰과 일치하는지 확인 (gray-700 vs gray-500 혼동 주의)
- [ ] **빈 상태 / 0건 / 로딩 중** 상태의 UI가 피그마에 있다면 구현되었는지 확인
