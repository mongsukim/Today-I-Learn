# iframe GA 이벤트 추적 삽질 회고

## 배경

자식 앱은 부모 앱(호스트) 안에 iframe으로 임베드되는 독립 프론트엔드다.
방문자 초대, QR 리더, 출입카드 등 기능이 iframe 안에서 동작하는데, 이 안에서 발생하는 GA(Google Analytics) 이벤트가 수집되지 않는 문제가 있었다.

## 왜 iframe에서 GA가 안 되는가

iframe은 브라우저 입장에서 **서드파티 컨텍스트**다.
Chrome의 SameSite 쿠키 정책으로 인해 iframe 내부에서 GA 쿠키(`_ga`, `_gid`)가 차단되어 이벤트 수집이 불가능하다.

## 해결 전략: postMessage 위임

iframe 안에서 직접 GA를 쏘는 대신, **부모 프레임(호스트 앱)에 이벤트를 위임**하는 방식을 택했다.

```
자식 앱 (iframe)                         부모 앱 (호스트)
─────────────────                        ────────────────
gaClick() 등 호출
  → sendEvent()
    → window.parent.postMessage(        →  useIframeMessaging 훅
        { type: 'GA_EVENT',                 case 'GA_EVENT':
          eventName, params },                window.gtag('event', ...)
        parentOrigin                      → GA4 수집 완료
      )
```

### 자식 앱 쪽 변경

- `libs/ga.ts`의 모든 GA 함수를 중앙 `sendEvent()` 함수로 통합
- embedded 모드 감지 시 `window.gtag` 대신 `window.parent.postMessage`로 이벤트 전송
- `initializeGA()`에서 embedded 모드면 gtag.js 로드를 건너뜀

### 부모 앱 쪽 변경

- `useIframeMessaging` 훅의 메시지 핸들러에 `GA_EVENT` case 추가
- 수신한 이벤트를 부모의 `window.gtag()`로 전달

## 삽질 과정

### 1단계: "GA가 안 잡혀요"

GA4 실시간 보고서에서 iframe 내 이벤트가 전혀 보이지 않았다.
실시간 > 이벤트 이름별 이벤트 수 > `click` > `event_category` 값을 확인했을 때
부모 앱 자체 이벤트만 보이고 자식 앱 이벤트는 없었다.

### 2단계: postMessage는 도착하는가?

부모 프레임 Console에서 수동 리스너를 걸어 확인:

```js
window.addEventListener('message', (e) => {
  if (e.data?.type === 'GA_EVENT') {
    console.log('📩 GA_EVENT 수신:', e.data)
  }
})
```

**결과: 도착함.** `event_category`, `building_name` 등 파라미터도 정상.

### 3단계: window.gtag는 존재하는가?

```js
typeof window.gtag  // → "function"
window.gtag('event', 'click', { event_category: 'test_manual' })
```

**결과: 정상.** 수동 호출한 `test_manual` 이벤트가 GA4 실시간에 즉시 찍혔다.

### 4단계: 그러면 왜 안 되는 거야?

gtag를 감싸서 GA_EVENT로 인한 호출이 있는지 감시:

```js
const origGtag = window.gtag
window.gtag = function(...args) {
  console.log('🔔 gtag 호출됨:', args)
  return origGtag.apply(this, args)
}
```

**결과: 🔔이 안 뜸.** postMessage는 도착하는데, `useIframeMessaging` 훅에서 `window.gtag()`를 호출하지 않고 있었다.

### 5단계: 혹시 코드가 배포 안 된 건 아닌가?

```js
document.querySelectorAll('script[src]').forEach(s => {
  fetch(s.src).then(r => r.text()).then(t => {
    if (t.includes('GA_EVENT')) console.log('✅ GA_EVENT 포함:', s.src)
  })
})
```

**결과: 아무것도 안 뜸.**

### 6단계: 근본 원인

**부모 앱 쪽 PR을 merge 안 눌렀다.**

자식 앱 쪽 코드(postMessage 전송)는 배포됐지만, 부모 앱 쪽 코드(GA_EVENT 수신 및 gtag 호출)가 개발 서버에 배포되지 않은 상태였다.
PR merge 후 배포하니 GA4 실시간에서 이벤트가 정상 수집되었다.

## 디버깅 과정에서 배운 것

### GA4 실시간 보고서 보는 법

- GA4 > 보고서 > **실시간 개요**
- 아래로 스크롤 > "이벤트 수(이벤트 이름별)" 카드
- 이벤트 이름(`click`) 클릭 > 매개변수 키(`event_category`) 클릭 > **값 목록** 확인

### iframe 디버깅 시 Console 컨텍스트 주의

Chrome DevTools Console 상단에 컨텍스트 드롭다운이 있다.
iframe이 있는 페이지에서는 `top`(부모)과 iframe origin이 분리되어 있으므로 **어느 컨텍스트에서 실행하는지** 반드시 확인해야 한다.

- `top` = 부모 프레임 (호스트 앱) → `window.gtag` 있음
- iframe origin = 자식 앱 → `window.gtag` 없음 (embedded 모드)

### postMessage 디버깅 체크리스트

1. **메시지가 전송되는가?** → iframe Console에서 `sendEvent()` 로그 확인
2. **메시지가 수신되는가?** → 부모 Console에서 수동 `addEventListener('message', ...)` 확인
3. **origin이 일치하는가?** → `event.origin` vs `targetOrigin` 비교
4. **핸들러가 실행되는가?** → gtag 래핑 또는 번들 내 코드 존재 여부 확인
5. **양쪽 모두 배포되었는가?** → 이번 삽질의 핵심

## 교훈

> iframe 통신은 **양쪽 서비스 모두 배포**되어야 동작한다.
> 한쪽만 배포하고 "안 된다"고 하기 전에, 상대편 PR 상태부터 확인하자.
