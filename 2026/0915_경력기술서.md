## 주요 성과
 
### ① 외부 결제 앱 복귀 시 WebView 복구 체계 수립  
 
**문제.** 결제 과정에서 카드사 앱으로 이탈했다가 돌아오면 WebView가 정상 복구되지 않아   
결제가 중단되는 문제가 반복되었습니다. 원인은 iOS와 Android의 WebView 생명주기가 서로 다르다는 점이었고, 
한쪽을 고치면 다른 쪽이 깨지는 상황이었습니다.  
 
**해결.**  
- iOS와 Android의 복귀 동작을 각각 분리해 **상반된 처방**을 적용했습니다.  
- iOS는 외부 페이지 상태에서 WebView 복구를 **건너뛰고**, Android는 앱 URL로 **강제 이동**시키는 방식입니다.  
- 카드사 앱 딥링크 실행 시 **미설치인 경우에만** 스토어 폴백을 타도록 분기해, 폴백이 결제 iframe을 통째로 날려버리던 문제를 제거했습니다.  
- 디버그 빌드에서만 실행 단계와 원본 URL을 남겨, 운영 로그에 민감 정보가 남지 않으면서도 재현이 가능하도록 했습니다.  
**결과.** 결제 복귀 실패가 해소되었고, 이 과정에서 규명한 플랫폼 차이를 **93줄 분량의 팀 규칙 문서**로 고정해 이후 유사 이슈의 재발을 차단했습니다.  
 
### ② 예약·결제 도메인 기획 문서 단독 작성 — 6,625줄
 
개발자로서 구현만 맡은 것이 아니라, **예약·결제 기능의 정책과 화면 기획 문서 전체를 직접 작성**했습니다.  
 
```
예약_결제_flow.md                        결제 상태 전이 및 예외 흐름
정책.md                                  취소 마감·환불·다회차 정책
화면기획_사용자앱_예약.md                  사용자 앱 예약 화면 정의
화면기획_사용자앱_노선다회차_검토.md         다회차 노선 예약 설계 검토
화면기획_관리자페이지_예약결제.md            관리자 페이지 예약·결제 화면 정의
+ HTML 프로토타입 3종
```
 
관리자 페이지 몫까지 포함해 **전량 단독 작성(6,625줄)**했습니다.   
기획-개발 간 해석 차이로 발생하던 재작업을 줄이고, 결제 정책 논의의 기준 문서 역할을 했습니다.  
 
### ③ QA 시나리오 문서화 → 스킬 자동화  
 
**문제.** 회원가입·약관 재동의·알림 등 분기가 많은 흐름에서 QA 누락이 반복되었고, 검증 기준이 담당자의 기억에 의존하고 있었습니다.  
 
**해결 — 3단계로 확장했습니다.**  
 
1. **시나리오 문서화 (3,064줄, 전량 단독)**  
   회원가입·로그인·약관 재동의 675줄, 노선 경로 694줄, 더보기 741줄, 알림 370줄 등 주요 흐름의 QA 시나리오를 분기 단위로 문서화했습니다.
2. **Figma 대조 검증**  
   구현 결과와 디자인 원본을 항목별로 비교한 검증 리포트를 작성해, 육안 확인에 의존하던 UI 검수를 기록으로 남겼습니다.
3. **도구화 (771줄)**  
   위 시나리오를 AI 에이전트 스킬로 재구성했습니다. 체크리스트·금지 패턴·디바이스 매트릭스·리포트 템플릿을 규격화하고 전용 커맨드를 만들어, **누구나 같은 기준으로 QA를 수행하고 동일 포맷의 리포트를 산출**할 수 있게 했습니다.
**결과.** 반복 QA가 개인 역량이 아닌 **재현 가능한 절차**가 되었습니다.
 
### ④ 앱 전역 네비게이션·에러 복구 안정화  
 
- **히스토리 스택**: 앱 시작 시 바닥 기준점을 보정하고, 완료 화면에서 상세로 이동할 때 `replace`를 적용해 뒤로가기 시 결제 완료 화면으로 되돌아가는 문제를 제거했습니다.
- **상태 복원**: 홈 화면의 탭·스와이퍼 페이지·스크롤 위치를 뒤로가기 시 복원하도록 구현했습니다.
- **오프라인 복구**: Android가 네트워크 capability 변화마다 발생시키는 `connected: true` 이벤트를 실제 네트워크 복귀와 구분해, 끊긴 적 없는 상태에서 전체 쿼리가 재발사되던 문제를 해결했습니다.
- **부분 실패 처리**: 목록 중 일부 상세 조회가 실패하면 카드가 사라져 제목만 남던 문제를, 해당 자리에 공통 에러 카드와 재시도 버튼을 노출하도록 개선했습니다. React Query v5의 `refetch`가 상태를 `pending`으로 되돌리는 동작을 별도 훅으로 흡수해 **9개 화면에 일괄 적용**했습니다.
- **네이티브 빌드**: dev 빌드의 `Info.plist`에 결제·본인인증 URL 스킴 44개가 누락되어 개발 환경에서만 앱 복귀가 동작하지 않던 문제를 찾아, 두 타깃이 단일 plist를 공유하도록 구조를 정리했습니다.

### ② 운영 중단 없는 v1 → v2 점진 마이그레이션 전략 수립
 
**문제.** 운영 중인 대규모 서비스의 UI를 전면 개편해야 했으나, 일괄 교체는 회귀 위험이 컸습니다.
 
**해결.** Strangler Fig 방식의 전환 규칙을 설계하고 문서화했습니다.
 
- **기존 컴포넌트는 수정하지 않는다** — v2는 별도 디렉터리에 신규 생성
- **페이지 단위로 교체한다** — v2 페이지는 v2 컴포넌트만 참조
- **테마 Provider로 토큰을 분리한다** — 같은 클래스명이 버전별로 다른 값을 갖도록 처리
- **환경변수 피처플래그로 전환한다** — 화면별 독립 롤백 가능
- **위험 신호 체크리스트를 둔다** — 규칙 위반을 조기에 감지
**결과.** v1/v2가 동일 서비스에서 공존하며 화면 단위로 안전하게 전환되고 있습니다.

## 강점
 
**하이브리드 앱의 경계 영역을 다룹니다.** 브라우저에서 재현되지 않고 특정 OS·특정 빌드에서만 나타나는 문제를 추적해 원인을 규명하고, 플랫폼별로 다른 해법을 설계합니다.
 
**도메인을 이해하고 구현합니다.** 결제 정책과 예약 규칙을 직접 문서로 설계한 경험이 있어, 요구사항을 받아 구현하는 것을 넘어 정책 단계에서 엣지 케이스를 제기할 수 있습니다.
 
**개인 경험을 팀 자산으로 전환합니다.** 두 프로젝트 모두에서 기술 표준 문서를 주도 작성했고, 반복 작업(QA)을 절차화한 뒤 도구로 자동화했습니다.
 
## 앞으로 확장하려는 영역
 
현재 담당은 화면·도메인 계층에 집중되어 있고, 빌드 파이프라인과 CI/배포 영역은 팀 내 다른 구성원이 맡고 있습니다. 직접 수립한 코딩 규칙과 QA 절차를 CI 게이트로 연결하는 작업, 그리고 라우트 단위 코드 스플리팅을 통한 초기 로딩 개선을 다음 과제로 보고 있습니다.
